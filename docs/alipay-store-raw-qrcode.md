# 支付宝门店账单：二维码接口直出

版本：`store-bill-1.3.0`。运行时代码只修改 `AlipayStoreBillReceiptPayment`，不修改易支付公共入口、账单监听协议或商城代码，不需要数据库迁移。

## 配置

编辑“支付宝门店账单收款”的插件配置，将“二维码接口输出”（`receipt_qrcode_output`）设为“支付宝原始二维码”（`raw`），最大金额偏移设为 **0 分**，填写该门店支付宝收款码解析后的**内容**（不是图片地址）。默认值仍为 `cashier`，旧配置升级后继续使用 mpay 收银台。

dujiaonext 继续使用原有 mpay 易支付商户渠道、协议版本和凭证，仅把交互模式设为“二维码”。轮询池内每个需要直出的门店配置均需启用上述选项。

## 返回与边界

只有易支付 V1/V2 的 API 网页支付下单、非 `jump` 设备、零偏移配置、本单快照实付金额与原金额一致，且快照有非空二维码内容时，插件才返回标准 `qrcode` 展示结果。V1 接口输出 `qrcode`；V2 输出 `pay_type=qrcode`、`pay_info=原始收款码内容`。不符合条件时保留原 `receiptQrcode` 收银台结果，只有图片时不会把图片地址当作二维码内容。

页面支付入口（跳转模式）保持原样，仍进入 mpay 收银台，不直接跳转支付宝。API 原码订单随后访问页面入口时也只进入原 mpay 支付页；保留的 `receiptQrcode` 参数供原页面使用。

原有门店选择、金额占用、订单快照、有效期、账单匹配、异步回调和重复请求复用均不变。旧订单不会因为修改插件配置而重新分配金额、换码或延长有效期。**已经从页面模式创建的订单再请求 API，仍复用原收银台结果**；验证新功能请创建新订单。过期或终态订单不会通过重复 API 请求重新下发二维码。

静态门店码不会因此自动填入金额；请由商城提示用户按订单金额支付。一个门店的同一金额在有效期内仍只能被一笔订单占用。订单到期不等于支付宝静态码失效，不应在过期后继续付款；请使商城提示和识别有效期一致。

## 验证

新增 `tests/store_raw_qrcode_unit.php` 和 `tests/store_raw_qrcode.php`，纳入原 CI 的 PHP 8.3/8.4 测试矩阵。覆盖默认兼容、原码输出条件、图片回退、非零偏移、快照复用、V1 MD5 与 V2 RSA 签名、页面入口不变、同金额占用、过期回退；同时运行原有数据库并发、付款通知、重复下单、浏览器和容器冒烟测试。

测试使用隔离数据库及测试密钥，不访问真实支付宝、不发起真实付款。真实支付宝扫描付款与 dujiaonext 页面验收需在部署后用新订单验证。
