# 支付宝门店账单：金额占用感知选路

仅影响 `alipay_store_bill_receipt`。不新增配置开关或数据表，不修改 receipt-watcher、流水格式、回调校验或其他插件的金额分配方式。

## 下单行为

正式下单先执行原有通道资格筛选（商户归属、轮询组、启停、支付类型、金额区间、日限额等），再按既有路由策略形成候选顺序：

1. 在允许的候选门店中优先寻找**原金额**。例如 A 的 100.00 已占用，即使 A 的 100.01 空闲，也先尝试 B 的 100.00。
2. 原金额候选全部不可用或被并发请求抢占后，才按每家门店原有 `amount_offset_max` 逐分向上尝试。偏移上限 0 表示严格原价，不会自动加价。
3. 所有候选及其允许偏移均不可用时，返回“当前可用门店的该金额均被占用，请稍后重试”，异常数据 `reason_code=receipt_amount_occupied`。不等待、不无限循环，不将门店永久禁用。

顺序轮询每次正式选路最多推进一次游标，并从本次起点环形向后尝试。权重模式按权重不放回排列，默认优先模式保持原有优先级；原金额阶段始终先于偏移阶段。同一阶段对同一收款配置去重。包含其他插件的混合路由中，其他插件只参加第一阶段；没有门店插件的路由仍使用原来的候选与派发机制。

后台**指定通道测试**不换店，只使用指定门店自己的金额范围。管理端路由预览和收银台支付方式预览均只读，不创建订单、不预占金额、不推进或续期轮询游标。

## 占用口径和并发边界

预检与最终分配共用查询条件：同一门店插件配置关联的**全部通道**，已有 `personal_receipt.receipt_amount`、处于可变订单状态、`expire_at` 未到期。按实际识别金额（整数分）比较，排除当前支付单自身。占用范围不局限本次轮询组或商户，停用关联通道上的未结束有效占用仍计算。只有支付单而尚未分配快照的记录不占用金额。

门店配置拓扑继续由现有 `AlipayReceiptGuard` 校验：相同账号和门店不能用两个启用配置重复承接收款。没有另建 Redis 占用缓存或定时同步任务。

只读预检是当时的快照，不保证金额仍然空闲。最终分配在持久化 Guard 保护下重新查询，与业务单、支付单、服务费冻结、资金流水和 `active_pay_no` / `attempt_count` 更新位于同一事务；冲突整体回滚，再尝试下一家。Guard 在业务单和账户锁之前获取。事务中没有插件派发或外部网络请求。

只对**提交前**的专用金额占用异常换店。配置错误、数据库错误、支付结果未知和提交后派发异常都不会伪装成金额占用自动重试。既有产品不支持异常仍沿用原有安全切换边界。

已有识别快照不会因刷新二维码而重新分配金额、延长有效期或更换二维码。调用方传入的门店识别快照不能覆盖服务端分配结果。已有活跃支付单继续使用原有重复请求保护。成功、关闭或过期按原有状态规则释放占用；历史快照和迟到流水校验不删除、不放宽。

## 诊断与测试

路由结果新增 `receipt_amount_state`（`original_available` / `offset_only` / `occupied`）及中文原因，保留临时跳过原因。日志记录商户订单号、通道、金额和阶段，不输出账号密钥、账单凭证或二维码。金额占用不是上游故障。

测试必须使用独立测试库，`DB_DATABASE` 以 `mpay_test_` 开头并与 `MPAY_TEST_DATABASE` 一致。现有集成测试会执行建表迁移，应使用空测试库，禁止指向生产库。

```sh
php tests/store_rules.php
php tests/store_integration.php
php tests/store_concurrency.php
php tests/store_routing.php
php tests/store_routing_concurrency.php
```

新增测试覆盖完整选路/下单/回调、原价优先、偏移兜底、跨通道占用、只读预览、顺序和权重模式、指定通道、重复请求、费用回滚、配置变化及提交后错误不换店。跨进程测试用同步屏障强制“多笔请求均预检为空闲，再并发分配”，检查金额唯一性、真实事务回滚及同一业务单幂等。全部使用合成流水，不调用真实支付宝扣款或查询接口。
