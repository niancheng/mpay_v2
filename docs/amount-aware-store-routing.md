# 支付宝门店账单：金额优先轮询

## store-bill-1.2.0 升级说明

本版将 1.1.0 自动叠加到旧策略上的金额感知，改为**显式选择的独立策略**：`route_mode=3`，后台名称“金额优先轮询”。只支持 `alipay_store_bill_receipt`（支付宝门店账单收款）。普通支付宝账单及其他插件暂不支持，不修改 receipt-watcher 或流水协议。

**升级后需手动选择新策略才有跨店原金额优先。** 不自动改写任何已有轮询组或商户路由偏好；旧编号 0/1/2 和原有配置保留。已有已展示支付单不重新选路，刷新不修改金额、门店、二维码或有效期。

## 开启方式

1. 更新镜像为 `ghcr.io/niancheng/mpay_v2:store-bill-1.2.0`，保留现有环境配置和数据挂载。
2. 管理后台编辑对应轮询组，将“路由模式”设为“金额优先轮询”，按编排排序号排列门店通道。排序号小的在前，相同时按通道 ID 升序。
3. 商户配置了支付方式路由偏好时，商户设置优先于轮询组；在商户端“通道选择方式”选择同一新策略。刷新页面以重新载入策略字典。
4. 严格不变金额时，各门店“最大金额偏移(分)”设为 0；保留非零值则允许第二轮按配置兜底。

新策略只使用合格的门店插件通道。混合候选中普通账单等未适配插件会被明确排除，路由预览显示“金额优先轮询暂仅支持支付宝门店账单收款”。全部不支持时明确拒绝，不隐式降级为旧策略或普通插件。

本版不新增数据库表、迁移或环境变量；复用已有 `route_mode` 字段和金额分配保护。前端使用现有后端字典/商户设置返回的策略选项，无需修改压缩后的 JS。

## 两轮规则

共同前提：先按原有规则筛选商户权限、启停、支付方式、金额区间、日限额等。每次**新的支付选路**均从排序第一家开始，不使用 Redis 轮询游标、权重或默认通道标记。

**第一轮：严格原金额。** 按 A → B → C 检查；A 原金额占用就尝试 B。即使 A 可以加价，也优先选后面的原金额。

**第二轮：原金额均不能分配时，从头按插件配置。** 再从 A → B → C 检查，使用第一家能在自己配置范围内分配金额的门店；全部不可用则报错。第二轮重新检查完整的合格门店列表，包括预检已满、零偏移或第一轮曾经冲突的门店，允许使用期间刚释放的原金额，不强行复用占用金额。

兜底不是“跨店最小加价”：A 可加 5 分、B 可加 1 分时，仍优先 A。每家门店内部仍逐分选择最小空闲金额，且不超过自己的 `amount_offset_max`。

此策略不保证订单量均衡：不同金额都空闲时，连续订单可以一直使用第一家。需要均衡起点时继续选择原来的顺序/权重策略。

## 原三种策略

- `0` 顺序依次轮询：仍使用共享游标确定本次通道；选中后按插件自身配置分配金额，不因为门店原金额占用而先跨店寻找原价。
- `1` 权重随机轮询：保留原权重选择与候选切换方式，不执行金额优先预检。
- `2` 默认启用通道：保留默认优先规则，选中后在该门店内部按插件配置处理。

这三种策略都不再因门店金额用尽而使用新增的占用换店逻辑。原有“本地支付产品不可用”安全切换仍保留。金额分配仍与订单、费用同事务，拒绝时完整回滚；恢复策略语义不等于撤销安全保护。

后台指定通道测试不参与路由，不换店。管理端、商户端和收银台预览均只读，不推进或续期轮询游标、不预占金额。

## 金额占用与安全边界

占用检查覆盖同一门店配置关联的全部通道，不限本次轮询组、商户或启停状态。只统计已有识别快照、处于可变状态、尚未过期的支付单，按实际识别金额（整数分）比较。一个门店配置重复绑定多个通道不会增加金额容量。

预检是瞬时快照。最终分配复用 `AlipayReceiptGuard`，与支付单创建、业务单更新、服务费冻结、资金流水及尝试次数同事务；金额抢占冲突完整回滚，新策略才继续下一候选。正式下单仍会对预检已满的候选做有界复查；预览则按当前快照报告是否可用。

只捕获提交前的专用金额占用异常。配置错误、数据库错误、未知支付结果及提交后派发错误不触发金额换店。事务中不做插件派发或外部网络请求。已有活跃支付单、重复请求与流水防重放保持既有保护。

## 后续合并上游的改动边界

`AmountPriorityRouteStrategy` 独立负责门店候选分阶段。公共 `PaymentRouteResolverService` 只增加按枚举值调用的入口，并删除 1.1.0 的隐式门店分支和旧策略金额感知重排方法。`PayOrderAttemptService` 仅以显式策略限制分阶段、收款范围去重与金额冲突换店。

其余变动为枚举/字典/校验、商户预览只读标记及可用性回填、版本文件和测试文档。金额分配服务、普通账单插件、资金和回调实现不改；未引入通用插件框架或新的配置表。

## 验证

使用独立 MySQL/Redis 测试环境；测试库必须以 `mpay_test_` 开头且与 `MPAY_TEST_DATABASE` 一致。禁止指向生产库。

```sh
php tests/store_rules.php
php tests/store_integration.php
php tests/store_concurrency.php
php tests/store_routing.php
php tests/store_routing_concurrency.php
```

`store_routing.php` 包含 `amount_priority_routing.php`，验证后台保存、商户覆盖、默认/权重忽略、固定排序、每次从头、原金额优先、排序优先偏移兜底、预检后释放和抢占、混合插件隔离、旧三策略回归及真实商户预览入口。跨进程测试由同步屏障让多个请求都先完成预检，再同时分配，验证金额唯一性、完整回滚及相同业务单幂等。

以上测试使用合成订单和账单，不调用真实支付宝支付或查询接口。
